# Grounding Rules — the anti-hallucination contract

Every output of this skill must trace to a real pull or a verified graph edge. These rules are enforced by `scripts/verify.py`, which runs before any report is built. **If verify fails, no report is emitted — full stop.** This is not advisory; it is a gate.

## The five rules

1. **No number without a source.** Every metric value carries `source` (the MCP call / metric key) and `window`. A measured value with no source is a violation. Null/error pulls are written as `DATA_NOT_AVAILABLE` and excluded from scoring — never guessed, never interpolated, never "estimated from typical brands."

2. **No dollar without a formula.** Revenue $ = `baseline × elasticity × headroom`; profit $ = `revenue $ × CM2 − incremental cost`. `verify.py` recomputes every figure from its stored inputs and fails on any mismatch. The model never free-hands a dollar amount.

3. **No "why" without an edge.** Every causal claim — the why-chain, the dials, the play rationale — must correspond to an edge in `funnel-edges.csv`. The chain is generated by `score.py` (max-product path through the graph); the model may not author causal links. A claimed `A → B` that isn't in the graph is a violation.

4. **No play without a real entity.** A play that names a campaign, flow, or offer must reference an entity present in the pulled inventory (`inventory.csv`). "Scale the Ghost-Campaign retargeting set" fails if no such campaign was read. If inventory wasn't pulled, plays must be marked `grounded:false` and phrased generically — the skill says "connect campaign data for specific plays" rather than inventing specifics.

5. **No recommendation without a chain.** Every play states `target_metric → intermediate_metric → outcome_metric` plus a `why`. `verify.py` checks the metrics are real nodes, the `target→intermediate` step is a real edge, and `intermediate` actually reaches `outcome`. This is what makes the brief teach: you see which dial moves which metric to help which outcome, and why.

## Pre-pull integrity gate — selective (run first)

Two checks, gated separately (see SKILL.md Step 1.5). Do not over-block:
- **Funnel source = Shopify.** Revenue, orders, AOV, sitewide CVR, checkout completion, cart abandonment come from Shopify and are reliable even when channel attribution is broken. The only hard STOP is when no Shopify / financial source is connected — then those values are `DATA_NOT_AVAILABLE`, never invented.
- **Attribution coverage = GA4/CAPI.** Governs *which channel gets credit*, nothing else. <70% paid coverage or CAPI >15% off Shopify → flag the channel-level paid levers (ROAS by campaign, channel CVR) as low-confidence; this does NOT block the Shopify-sourced funnel brief.
- A broken pixel mimics a performance drop, but it does not make Shopify's order / AOV / CVR numbers wrong. Note both results in the run's evidence.
- **Denominator integrity.** If `orders ÷ sessions` is implausibly low for the AOV tier, the site carries non-shopping traffic (software / community / app). Suppress the sessions-based CVR lever and use the Shopify checkout funnel (`orders ÷ (orders + abandoned_checkouts)`) instead. A polluted denominator is a hallucination risk — it manufactures a fake "conversion crisis."

## Confidence labels (always visible)

Each scored lever and each play carries a confidence tag:
- `measured` — pulled this window with a source.
- `needs spend input` — paid-lever profit can't be computed without an incremental-spend assumption; shown as `—`, never faked.
- `UNVERIFIED` — would fail the gate; must be fixed before the report builds.

## Calibration honesty

Edge **strengths** are hypothesized until the cross-account calibration pass replaces them with measured coefficients. The ranking is therefore directional, and every report says so in the footer. The *structure* (which levers, which direction, which chain) is verified; the *exact ordering* sharpens with data. Never present the ranking as precise.
